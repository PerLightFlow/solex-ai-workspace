# 用户共享空间改造

## 使用规则

每个账号固定一个个人空间。个人空间没有成员邀请和空间切换入口，聊天、附件和生成产物保持个人私有。管理员统一配置模型、工具和运行环境，不因本次改造扩大其对私人聊天的读取权限。

共享空间直接邀请邮箱对应的个人账号。对方在工作台接受邀请后加入，默认角色为“使用者”；邀请有效期 7 天，可撤销。编辑者可上传和维护获准编辑的内容，管理员可维护成员，所有者负责移交、归档和解散。管理员不能直接提升同级或所有者权限。

| 操作 | 使用者 | 编辑者 | 管理员 | 所有者 |
| --- | --- | --- | --- | --- |
| 阅读已授权内容、使用智能体 | 是 | 是 | 是 | 是 |
| 编辑空间自有内容 | 否 | 是 | 是 | 是 |
| 修改共享的个人原件 | 否 | 原件授权后 | 原件授权后 | 原件授权后 |
| 下载共享原文件 | 原件授权后 | 原件授权后 | 原件授权后 | 原件授权后 |
| 维护空间成员 | 否 | 否，允许退出 | 受角色边界限制 | 是 |
| 移交、归档、解散空间 | 否 | 否 | 否 | 是 |

个人知识库共享采用原件引用，默认不开启“允许修改原件”和“允许下载原文件”。接收方管理员不能提高原件授权，也不能擅自再次分享。共享空间可以直接创建自有知识库和智能体；资源移交后，原创建者身份不再等同于管理权限。一个资源经多个空间获得权限时取有效权限并集，界面展示来源；撤销一条路径不会错误撤销其他有效路径。

共享智能体必须使用“指定知识库”或“不使用知识库”。作者本人和目标共享空间都必须已获知识库授权，不能依赖作者的“全部个人知识库”。成员撤回、知识授权变化后，后续请求和工具调用重新检查权限，进行中的 Agent 运行也监测撤权。已阅读、复制或下载到系统外的内容不属于可撤回范围。

## 内容维护与恢复

- 文件显示上传人、上传时间、人工修改人和时间；自动解析不冒充人工编辑。
- 文档原件修改保留内容版本，保存和恢复带版本校验，旧页面写入返回冲突。Wiki 也校验当前版本，恢复产生新版本。
- 知识库的“版本与回收站”入口可以查看原件历史和恢复删除内容；Wiki 与分块保留各自版本编辑器。
- 默认保留 30 个手工版本、30 个自动 Wiki 版本，回收站 30 天。系统管理员在“系统管理 → 内容保留策略”统一调整，对所有个人空间和共享空间生效，空间成员不能单独覆盖。已有回收站项目的到期时间保持不变。
- 原件历史只对当前仍有权限的用户开放；通过共享获得的历史读取还受授权开始时间限制。
- 空间归档后可以阅读，协作写入暂停。非空空间不能直接解散，所有者退出前必须移交。
- 系统管理员可在“离职空间交接”处理已停用所有者的共享空间和已经共享给该团队的原件；不会转移私人聊天或把未共享个人资料暴露给其他团队。

2026-11-06 将内容保留策略入口从共享空间页移到系统管理，并补充全局适用范围及生效说明；后端继续使用现有全局策略记录与系统管理员权限检查。

## 技术入口

- `weknora/internal/spaces/`：账号成员、资源归属、授权并集、版本、回收、运行检查和受保护文件链接。
- `weknora/internal/handler/user_spaces.go`、`space_history.go`、`space_lifecycle.go`：`/api/v1/spaces` 接口及旧接口兼容限制。
- `weknora/frontend/src/views/organization/UserSpaces.vue`：成员、资源、权限来源、移交和空间设置。
- `weknora/frontend/src/composables/useSpacePermission.ts`：按真实资源权限控制编辑、下载和预览入口。
- `weknora/frontend/src/views/knowledge/KnowledgeHistory.vue`：原件版本和回收站。
- `deploy/solex-runtime/migrate-user-spaces.py`：只读盘点、指纹核对、用户与资源权限比较和事务迁移。
- `SOLEX_USER_SPACES=true` 启用新模型；物理 tenant ID 继续作为存储和索引分区，不代表个人或团队资源的最终访问权。
