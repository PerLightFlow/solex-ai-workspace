# SOLEX 统一运行配置

本发布把模型和基础设施配置权限交给系统管理员，保留普通用户的个人空间、聊天、知识库、智能体创建与业务提示词编辑。

默认提示词以 `Solex` 介绍助手，不包含研发公司归属。完整发布包同时复制明确列出的公共提示词模板及 `builtin_agents.yaml`，不打包本地 `config.yaml` 或模型凭据。技术模块名、稳定模板 ID 和上游许可证保留。

公共默认模板随完整发布更新；数据库中管理员已保存的自定义提示词不会被覆盖。已完成的一次性品牌数据迁移工具已移除，历史实现保留在 Git。

## 行为

- `SOLEX_MANAGED_RUNTIME=true` 启用；默认关闭，保持上游行为。
- `SOLEX_RUNTIME_TENANT_ID` 指向管理员维护默认模型及联网搜索的配置空间。它不是用户数据空间，不改变任何聊天、文件、知识库或记忆的归属。
- 聊天每次运行读取公共默认模型。新知识库自动选定公共 Embedding/生成模型；已有知识库的 Embedding ID 保留，管理员换默认模型不会迁移已有索引。
- 管理员创建的模型和 MCP 服务发布为内置共享项。其他用户只能使用共享项；密钥仍只存后端。个人 OAuth 和浏览器授权不共享。
- 普通用户不能修改模型、MCP 服务连接、搜索供应商、存储/向量数据库、解析器、沙箱、技能安装或相关全局参数。后端路由和运行时检查共同约束，个人空间 Owner 身份不能绕过。
- 普通用户仍能创建智能体、编写提示词、选择知识库和已提供的工具，以及维护文档。可选视觉、语音、重排模型未配置时不宣称对应能力可用。
- 这次不新增跨租户沙箱或技能安装共享。当前原生部署关闭 Docker 沙箱；聊天和知识检索不依赖它。

## 智能体运行预算

系统管理员在“系统管理 → 系统设置 → 智能体运行”中统一配置：

| 设置 | 默认值 | 范围 |
| --- | --- | --- |
| 最大执行轮次 `agent.max_iterations` | 50 轮 | 1–200 轮 |
| 协作等待最短间隔 `agent.collaboration_wait_timeout_seconds` | 30 秒 | 1–60 秒 |

设置使用现有 `system_settings` 持久化、权限校验和操作审计，无需重启。在统一运行模式下，管理员和普通用户启动的新智能体运行都使用此配置；本版本启动的运行、子任务及暂停后的恢复保留启动时的快照。智能体编辑界面不再提供相互冲突的单独轮次设置。Skills 安装助手属于独立运维流程，保留其专用预算。升级前未记录预算快照的旧暂停任务，恢复时使用当前设置。

一轮是一次模型决策及其工具执行，不是一次用户发言。一轮内的多个工具不会分别计为多轮；`wait_agent` 仍然计轮次，但模型指定的短等待会提升到管理员设置的最短间隔。有新结果、状态变化或用户输入时可提前唤醒。等待没有无上限的轮次豁免。

协作主任务达到预算时，停止继续派发、收集已有结果并取消未完成子任务，然后尝试生成明确标记的阶段性答复。答复不能把未完成子任务描述为已完成；用户取消仍立即停止，模型汇总失败仍会向调用方返回失败。

发布验收检查管理员保存、非法参数拒绝和普通用户禁止修改，验证过程中不临时降低生产预算。边界收尾、等待和恢复行为另由 mock 模型回归测试覆盖；这不代表复杂真实任务的成功率或并发容量已经验收。

## 全局内置智能体

启用统一运行配置后，智能体页面中的内置智能体由系统管理员维护。管理员可添加、编辑和移除，保存后服务端对所有工作空间使用同一份定义。普通用户及个人空间所有者只能使用，个人自定义智能体继续按原权限管理。

- 系统目录保存于 `system_builtin_agents`，首次使用时从程序模板初始化。移除保留软删除记录，应用重启和默认配置加载不会把它重新补回。
- 移除不删除已有聊天和消息；后续请求该智能体会返回不可用，旧分享也不能绕过。已开始执行的请求不会因目录变更强制中断。
- 系统智能体在提问用户自己的空间执行，只能查询该用户有权访问的资料。全局配置禁止固定绑定管理员私人知识库、模型或工具连接；模型及运行环境继承系统配置。
- Wiki 修复、技能安装等内部流程智能体保留内部用途，不新增到普通聊天选择器或当前内置管理卡片中。
- 管理接口为 `/api/v1/system/builtin-agents`，仅真实系统管理员登录身份可调用；普通 `/agents` 写接口不能修改全局定义。个人 API Key 不获得全局管理权限。

系统管理员在智能体页面的“系统智能体”区域使用“新增系统智能体”，卡片菜单中可编辑或删除。删除确认提示影响所有用户；已打开页面在重新加载目录后更新显示，服务端后续调用立即按最新目录检查。

## 构建与发布

后端必须使用 Go 1.26 和兼容当前 Debian 12 运行层的 CGO 构建。前端执行类型检查、相关测试和生产构建。依赖、二进制、dist、密钥和发布包不提交 Git。

发布目录应包括 `release.json`、`app/` 后端镜像上下文（含与源码匹配的完整 PostgreSQL/SQLite 迁移）、`ui/` 前端镜像上下文、此目录中的 Python/入口脚本和校验清单 `SHA256SUMS`。镜像元数据必须记录完整源码提交。

`apply.sh` 在现有服务器受限发布入口下执行，先构建两个镜像、保存私有环境备份和数据库备份，再将原模型 ID 标记为共享并切换 app/frontend。数据库、文档解析、Embedding 和搜索服务不重建。

自动验收使用一个临时普通账号验证：模型继承、禁止配置修改、无需模型参数创建智能体/知识库、个人列表隔离、真实模型流式回答。测试结束删除合成智能体/知识库、禁用测试账号并撤销其会话（保留禁用账号和空测试空间供审计）；身份和清理状态保存在权限为 0600 的验收记录中。此验收不代表容量、OCR 或调研质量验证。

失败时只回退本次模型/MCP共享标记、运行环境和 app/frontend 镜像，不用整库覆盖恢复来丢弃发布期间的新数据。原始数据库备份只用于人工恢复。

当前发布使用 PostgreSQL 135 → 136、SQLite 52 → 53，新增文件上传人、最近修改人及人工修改时间字段，并从有明确人员身份的历史事件回填。发布前会额外构建“原应用二进制＋新迁移文件”的兼容回退镜像，并保存私有 `rollback.env`。这样回退时保留新增字段和发布期间的数据，同时避免旧镜像找不到数据库当前版本的迁移文件。上线和回退均检查数据库版本、dirty 标志及应用迁移错误，不能仅以 `/health` 返回 200 判断成功。后续若增加其他迁移，必须重新审查兼容性并更新发布脚本的版本门槛。

验收会创建一个合成系统智能体，验证普通账号可见、管理员和普通账号均可继承默认模型对话、管理员修改全员生效、普通账号无法管理、私人知识绑定被拒绝、移除后列表/Get/两种聊天入口不可用，然后清理测试数据。验收不删除原有内置智能体。

## 文件人员与操作记录

文件列表、卡片和详情展示上传人/上传时间及最后修改人/人工修改时间。后台解析、摘要和索引产生的 `updated_at` 不代表人工修改；来源无法确认时显示未知，不把知识库创建者当作上传人。

`GET /api/v1/knowledge/:id/activity` 在现有文件读取权限内提供操作人名称、动作、时间与修改字段。共享成员可以查看已获授权文件的记录；API 不返回原始审计详情、请求路径、邮箱或凭据。知识库配置和权限审计仍只对原有管理员开放。该历史复用审计日志的保留策略（默认 90 天），不是原始文件永久逐版归档；上传文件替换的旧源文件留存策略未改变。

发布验收使用合成资料验证两人上传/编辑归属、客户端伪造字段无效、后台处理不覆盖人工时间、标题/摘要/元数据操作记录、共享只读成员查看与游标分页、撤回共享后的拒绝访问；随后清理合成知识库和共享空间并停用验收账号。
